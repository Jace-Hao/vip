1. 项目概览

一套只读的门店数据工具：从「洗衣管家」软件里导出会员数据、逐会员详情和全部订单明细，生成离线可搜索的「会员数据查询台」，并配套一个带定时同步、自动关机、开机自启、自动清理的抓取操作台。

能力入口说明
会员导出（常规+全量字段）导出会员数据.cmd几秒完成，常规 9 列 + 档案全字段 62 列
逐会员详情导出（增量）导出会员数据(含详情).cmd标签/余额构成/卡券/订单号/最近充值；签名比对增量，只抓新增/变更
订单明细抓取操作台 或 fetch_orders.mjs逐单完整详情（衣物/照片链接/支付/状态历史），断点续传
会员数据查询台打开会员查询页面.cmd离线单页，搜索/筛选/订单详情/卡券/订单号反查
订单抓取操作台打开订单抓取操作台.cmd开始/暂停/进度/日志/定时同步/同步后关机/手动清理

原则：全程只读。所有取数通过软件的查询接口完成，不写入、不点击界面。

3. 取数原理（核心架构）

所有数据通过 CDP（Chrome DevTools Protocol，端口 9222）注入页面上下文，调用洗衣管家软件自身的查询接口：

找 9222 调试端口的目标页面
  → Runtime.evaluate 在页面内执行包装函数
  → 页面内用 $request 发软件自己的 XHR（带软件的登录态）
  → 拿到 JSON 返回
接口用途备注
getuinfo会员详情（含卡券、订单数）详情导出主接口
searchwashorders订单列表（按 uid 分页）start/size/currentPage/currenQuantity（注意拼写 curren）
getorderdetail单笔订单完整详情约 15.6KB/单：114 字段 + 衣物数组 + 三套照片 URL + 支付 plist + 状态历史
getordercloth订单衣物实测无需（getorderdetail 已含）

关键坑：页面内 $request 的回调在非成功时可能永远不触发 → 必须自带超时兜底（页内 25s + evaluate 外层 40s），否则整个流程挂死。

服务端限速：请求达到数百次后服务端会冷却（实测 30~40 分钟不响应），营业时段更严重（白天几乎全部超时）。应对策略（已内建）：失败自动等待 180 秒重试、断点续传、夜间定时同步避开营业时段。慢不丢数据，只要一直跑就能抓完。

5. 数据文件说明（接手必读）

5.1 带时间戳的导出产物

每次「含详情导出」或「定时同步」都会在 导出结果\ 生成一套同时间戳文件（_YYYYMMDD_HHMMSS）：

  • 会员导出_*.json / .csv — 常规 9 列 + 全量 62 列（json 含 fullRows，是查询台的会员主源）
  • 会员全量数据_*.csv / .json / .xlsx — 全量字段表
  • 会员详情_*.json / .xlsx — 逐会员详情快照（json 内 details 数组，1962 条/全量）

导出结果\订单数据\ 内：订单_*.json（单会员抓取产物）、会员订单_*.json（批量合并快照）、订单试点预览_*.html（试点可视化）。

5.2 点开头的文件 = 正在使用的运行数据（清理功能永不触碰，手动清理也请保留）

文件作用丢了会怎样
导出结果\订单数据\.orders_results.jsonl订单抓取基线：每行一个会员的完整订单 JSON（含 sig 签名、complete 标记）。增量比对、断点续传、查询台订单数据全部以它为主源下次同步把全部 1911 位有订单会员的订单重抓一遍（数小时）
导出结果\.detail_cache.json会员详情签名缓存（1962 条）详情增量失效 → 详情全部重抓
导出结果\.deep_results.jsonl详情抓取续传记录影响同上（较轻）
导出结果\.last_export.json最近一次导出的元信息无关紧要
导出结果\订单数据\.orders_run.lock抓取单实例锁（内容=PID，带存活检测）陈旧锁会被自动清理，无需手动处理
.sync_schedule.json（工具根目录）定时同步设置（enabled/time/shutdownAfter/lastFiredDate）定时设置回到默认（停用）

5.3 查询台数据

  • 查询页面\data.js（约 5.7MB）：会员列表 + 全部详情 + orderIndex/orderSearch（订单号反查会员）。
  • 查询页面\订单分片\part_NNN.js：订单详情按 60 人/片懒加载，页面用到哪片注入哪片。
  • 由 build_viewer.py 生成；它只读最新一份 会员导出_*.json 与 会员详情_*.json，订单以 .orders_results.jsonl 为主源、订单_*.json 为补充。

5.4 自动清理（v1.6 新增）

  • 规则：按文件名时间戳分批，保留最近 2 批，其余移入回收站（可找回）。
  • 触发：服务启动后 8 秒、每次抓取完成后（顺序：清理 → 刷新查询页 → 可选关机）、操作台按钮「清理过时数据」。
  • 被占用的文件（如正开着的 Excel）自动跳过。

6. 操作台与自动化机制

6.1 操作台服务（orders_server.mjs）

  • 地址 http://127.0.0.1:8791（仅本机）；由计划任务开机自启，或双击 打开订单抓取操作台.cmd（已有实例时只开页面）。
  • 状态机：idle → deep（详情增量）→ orders（订单抓取）→ done/failed，paused 为暂停。
  • API：GET /api/status、POST /api/start（{"sample":N} 可选）、/api/stop、/api/rebuild、/api/cleanup、/api/schedule（GET/POST）、/api/cancel_shutdown、/api/open。
  • 抓取流水线：export.mjs --deep（详情增量）→ fetch_orders.mjs --all（订单，sig 比对跳过未变会员，complete:false 的自动补抓）。
  • 失败处理：成员级失败等 180 秒重试一次；成员内失败订单等 180 秒统一重试一轮；仍失败标记 complete:false，后续运行自动补抓；连续失败过多自动停止（保留进度）。
  • 单实例锁 .orders_run.lock（PID 存活检测）；重复自启的实例会因端口占用静默退出，且不会误删抓取中的锁。

6.2 定时同步（页面设置，存 .sync_schedule.json）

  • 触发条件（全部满足）：已启用、当前时间与设定时刻相差 ≤10 分钟、今天还没触发过、无正在运行的任务、锁文件不存在（或已死）。
  • 到点流程：确保洗衣管家在调试模式（端口不通 → 自动 taskkill 后带 --remote-debugging-port=9222 重启，最多等 90 秒）→ 详情增量 → 订单抓取 → 自动清理 → 刷新查询页 →（勾选时）约 2 分钟后关机。
  • 任一环节失败都不会关机（软件重启失败、同步取消等情况直接终止本次定时任务）。
  • 关机倒计时 120 秒，页面顶部红色提示条可一键取消（shutdown /a）。
  • 错过设定时刻超过 10 分钟视为错过，次日再触发；每日循环，直到用户停用。

6.3 开机自启

  • 计划任务 XQY-Orders-Console：登录 Windows 后 30 秒，wscript 隐藏运行 开机自启-操作台服务.vbs（无窗口、不弹浏览器）。
  • 重装：双击 安装开机自启.cmd；移除：移除开机自启.cmd。
  • 关机后次日开机登录，服务自动就位 → 当晚定时同步照常。

7. 安全红线

  1. 会员数据绝不进仓库、绝不外传。.gitignore 覆盖：导出结果/、查询页面/data.js、查询页面/订单分片/、.dev/、.sync_schedule.json 等。每次 commit 前核对 git status，出现数据文件立即中止。
  2. 对洗衣管家只读：只调查询接口，不写数据、不点界面。
  3. 营业时间不重启洗衣管家（店员正在使用；需要调试端口时等打烊或与店员协调）。
  4. 查询台/导出文件仅限门店内部使用。

9. 已知限制与踩坑记录

#事项说明 / 对策
1服务端限速约 400 次请求后冷却 30~40 分钟；营业时段更严重。内建 180 秒等待+重试+续传，夜间跑最稳
2$request 回调不触发非 success 时回调可能永不执行 → 所有调用必须带超时兜底
3build_viewer 只取最新会员导出_*.json/会员详情_*.json 各只读最新一份；自动清理保留 2 批与其兼容
4订单快照时间差会员数据（列表）比订单抓取晚时，会出现「5 笔 vs 4 笔」——查询台已做合并显示（摘要卡+待补抓标注）
5服务内状态 vs 模块级变量start() 会重置 state 对象；scheduleTriggered 这类跨阶段标记必须放模块级，且 deep 失败/暂停路径都要复位（否则可能在错误时机关机）
6重复实例与锁端口占用时自启实例静默退出；process.on('exit') 清锁前必须检查锁内 PID 是否存活，防止误删抓取中任务的锁
7仓库文件名大小写仓库里是小写 readme.md（Windows 大小写不敏感，git add README.md 不报错但也不生效）
8临时目录会被清理.openclaw\tmp 类临时目录有外部自动清理机制，重要产物必须落进项目目录或入库
9jsonl 过期fetch_orders.mjs 中 jsonl 超过 7 天未更新才会重置（v1.6 前是 20 小时，跨天续传会全量重抓）
10git 提交显示乱码控制台 GBK 显示问题，实际提交内容是正确的 UTF-8，勿因此反复重试
